# ДЗ 5 — LoRA на собственном датасете pandas

На базе Qwen3-0.6B обучаются два адаптера: на всех 28 слоях и только на
слоях 14–27. Вход — **те же** `train.pt` и `val.pt` из
[ДЗ 4](https://github.com/aralmi/mlops26-hw4), 1388 и 154 примера.
Контрольные SHA256 и версия входа — в `docs/input_manifest.json`.
Для сокращения времени обучения на CPU использована фиксированная случайная
выборка: **256 train и 32 val**. Исходные файлы не меняются. Выбор задаётся
`train_limit`, `val_limit` и `subset_seed` в `params.yaml`; оба варианта
используют одни и те же примеры. Одна эпоха выбранного набора — 32 обновления
при эффективном батче 8. Это не полный проход по всем 1388 примерам.
Индексы выбранных примеров сохраняются в метриках; для полного набора
достаточно поставить оба лимита в `null` и повторить обучение.
Модель оценивается на валидации до первого шага, каждые 10 шагов и в конце;
пять фиксированных вопросов для сравнения относятся к pandas, а не к
преподавательскому медицинскому набору.

## Команды

В терминале, находясь в папке `hw5-broken`:

```bash
make install
make train
make compare
make check
```

`make train` запускает стадии DVC `train_all`, `train_freeze`, `plot`;
`make compare` запускает `compare`. Если входы и код не изменились, DVC
пропускает уже завершённое долгое обучение. `make check` сверяет девять
критериев на **текущих** артефактах, но делает два собственных коротких
трёхшаговых прогона для проверки воспроизводимости. Изменение `src/train.py`,
`src/data.py`, `src/runtime.py`, `src/config.py` или `params.yaml`
меняет отпечаток; тогда надо заново выполнить `make train`.
Оригинальный `tests/check.sh` не изменён; ожидаемый отпечаток `06a02208c1f0`.

`make status` показывает актуальность стадий, `make verify` выполняет
дополнительные unit-тесты. Повторный `make train` не обязателен для видео,
если DVC говорит, что данные и пайплайн актуальны.

Снижение loss не гарантирует правильность каждого ответа: в сравнении
есть ошибки и повторы. Подробности и ограничения — в `docs/defects.md`.
6 октября 2026 все девять исходных проверок и четыре дополнительных
unit-теста прошли. Отпечаток `tests/check.sh` — `06a02208c1f0`.

- `docs/curves.png` — train и val loss обоих вариантов, включая базовую
  точку val на шаге 0. Создаётся стадией `plot`.
- `docs/compare.md` — ответы базы и адаптера на пяти вопросах pandas.
  Создаётся стадией `compare`.
- `docs/defects.md` — пять исходных дефектов: причина, симптом, исправление,
  численное подтверждение из собственного прогона.
- `params.yaml` — модель, LoRA, параметры обучения, вопросы сравнения.
- `dvc.yaml` и `dvc.lock` — зависимости, результаты, снимок запуска.
- `metrics/*.json`, `models/`, `data/` — локальные артефакты DVC,
  исключённые из Git. У GitHub-клона без DVC remote адаптеров нет.

Обучение выполняется на CPU MacBook Air M2 (16 ГБ), в `float32`, с четырьмя
потоками и фиксированным PyTorch 2.9.1. На этом компьютере MPS-прогоны
давали нечисловые градиенты, в том числе до первого обновления весов.
При длине входа до 3456 токенов используются `batch_size=1`, `grad_accum=8`;
gradient checkpointing включается на входах от 1024 токенов. В `src/train.py`
лосс и градиент замороженной проекции на словарь вычисляются блоками по
128 целевых позиций. Unit-тест сравнивает их с обычным causal loss.

После оценки качества состояние LoRA, оптимизатора, scheduler и RNG
сохраняется в игнорируемую папку `.cache/checkpoints/`. Прерванный
`make train` продолжится с последней сохранённой точки, если код, конфиг
и данные совпадают. Диагностические прогоны `make check` выполняются заново.
Для обучения с нуля можно выполнить `uv run python -m src.train --variant
all_layers --fresh` и аналогично для `freeze14`.

## Воспроизведение и публикация

Тензоры взяты без изменения из ДЗ 4; DVC-указатель `tokenized.dvc`
версионирует их вне Git. Адаптеры остаются в локальном DVC remote
`../dvc_remote` (относительно проекта). Он **не** публикуется на GitHub.
Чтобы получить те же веса на другом компьютере, требуется отдельно
передать DVC remote и выполнить `uv run dvc pull`. Иначе нужно скопировать
точные тензоры из ДЗ 4 и заново запустить обучение.
Базовые веса Qwen также должны быть доступны локально или скачаны из
Hugging Face; проверка переносимости адаптера использует их локальный кэш.

Для сдачи нужны ссылка на GitHub-репозиторий и видео с `make check`, где
видны все девять успешных проверок, финальная строка и отпечаток скрипта.
Детальный порядок показа можно обсудить после завершения обоих экспериментов.
